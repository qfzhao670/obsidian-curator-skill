# Obsidian 语法与特性指南（三功能共享）

整理笔记（①）和字幕生成（③）时参考本文件。这里给出 Obsidian Flavored Markdown（OFM）的语法速查、
各项特性的用法规则，以及一篇基于真实笔记的 before/after 示例（完整成品见 `example-curated-note.md`）。

## 1. 内部 wikilinks（双链）

### 语法

| 用途 | 语法 |
| --- | --- |
| 链接笔记 | `[[笔记名]]` |
| 链接到标题 | `[[笔记名#标题]]` |
| 链接到块 | `[[笔记名#^块ID]]` |
| 别名（显示名） | `[[笔记名\|别名]]` |
| 同笔记内标题 | `[[#标题]]` |
| 嵌入笔记/图片 | `![[笔记名]]`、`![[图片.png]]` |
| 图片指定宽度 | `![[图片.png\|300]]` |

- 内部关联用 `[[wikilinks]]`（改名时 Obsidian 自动更新）；对外部网址才用 `[文字](url)`。
- 句中非专名概念用别名小写显示，如 `[[Gradient Descent|gradient descent]]`。

### 用法规则

- **链接要嵌在正文里、有实际关联意义的位置**，而不是在文末堆一个「相关笔记」列表——那种空泛的链接列表没有用处。
  - 一句话 / 一段 → 另一篇的某个标题：`[[笔记名#标题]]`
  - 某个标题 → 另一篇的某一段（块）：`[[笔记名#^块ID]]`
  - 一句话 → 另一整篇：`[[笔记名]]`
- 只链接 vault 中**真实存在**的笔记，或明确可作为独立条目的概念；无法确认存在时用别名形式（如 `[[RAM|内存]]`），宁缺毋滥。
- 只在**确有链接意义**时建链：知识库还小、笔记之间尚无实质关联时，不加内部链接是正常的，不要硬凑。
- 这是 Obsidian 图视角 / 反向链接的核心价值：把有真实关联的知识点连起来，而不是生造关系。

## 2. 标签 + frontmatter

### 语法

- 正文：`#标签`、嵌套 `#标签/子标签`。
- 可写在 frontmatter 的 `tags` 字段里。
- 规则：可含字母、数字（不能开头）、下划线、连字符、斜杠。

### Frontmatter（文件顶部 YAML）

```yaml
---
tags:
  - cs/hld
aliases:
  - 别名一
source: 来源
---
```

- 常用字段：`tags`、`aliases`（别名，便于链接提示）、`source`。

### 用法规则

- 文件顶部加 YAML frontmatter：`tags`（含嵌套，如 `#cs/hld`）、`aliases`、`source`（来源课程/视频等）。
- 正文中可为关键主题加 `#标签`。

## 3. Callout 摘要框

### 语法

```
> [!note] 可选标题
> 内容……
```

- 常用类型：`note`、`tip`、`warning`、`danger`、`info`、`success`、`question`、`example`、`abstract`（别名 `summary`/`tldr`）、`todo`、`bug`、`failure`。
- 折叠：`> [!faq]-`（默认折叠）、`> [!faq]+`（默认展开）。

### 用法规则

- 用于「关键结论 / 总结 / 注意」，每篇最多 1–2 个。
- 常用类型：`note`（小结）、`tip`、`warning`（注意）。

## 4. 外部链接

### 语法

- `[文字](https://...)`。

### 用法规则

- 只链接**公认官方文档**：Jenkins、Nginx、Sentry、PM2、GitHub Actions、CAP 定理等有官方站点的内容。
- 拿不准的 URL 一律不加，绝不杜撰。

## 其它

- 高亮：`==文字==`。
- 表格：标准 Markdown 管道表格，仅在「对比 / 多列数据」时用。

## Before / After 示例

### Before（原文，笔记 `1.Computer Architecture.md`）

```markdown
![[Pasted image 20260822095327.png]]

计算机只理解二进制的0和1，这些用比特表示。一个比特是计算中最小的数据单位……从这里扩展，我们有千字节、兆字节、吉字节和太字节。

## 磁盘存储
为了存储这些数据，我们有计算机磁盘存储……它可以是==HDD或SSD==类型。磁盘存储是非易失性的……虽然SSD更贵，但它们提供的数据检索速度明显快于HDD。例如，一个SSD的读取速度可能在每秒500兆字节到3500兆字节之间……

## RAM
磁盘之后的下一个直接访问点是RAM……这是一种==易失性存储器==……它们的读写速度通常超过每秒5000兆字节……

## 缓存
……==L1缓存只需几纳秒==。CPU首先在L1缓存中查找数据……最后才检查RAM……

## CPU
……CPU是计算机的大脑，它负责获取、解码和执行指令……==编译器==执行此翻译……

## 主板
最后，我们有主板……它提供了允许数据在这些组件之间流动的路径。
```

### After（整理后，要点）

```markdown
---
tags: [cs/hld, cs/computer-architecture]
aliases: [计算机组成]
source: System Design 课程笔记
---

# 计算机体系结构

计算机只理解二进制的 0 和 1，用比特（bit）表示……一个字节（byte）由 8 个比特组成……

![[Pasted image 20260822095327.png]]

## 存储层次

从慢到快、从大到小，存储组件依次为磁盘、内存、缓存。

### 磁盘存储
- **类型**：==HDD 或 SSD==
- **特性**：非易失性；存放操作系统、应用程序与所有用户文件
- **速度**：SSD 约 500–3500 MB/s，HDD 约 80–160 MB/s

### RAM（随机存取存储器）
- 保存当前正在使用的数据结构、变量、应用数据
- **特性**：==易失性==——重启后数据可能不持久
- **速度**：通常 >5000 MB/s，快于最快的 SSD

### 缓存（Cache）
- 比 RAM 更小、更快（==L1 缓存仅需几纳秒==）
- 查找顺序：L1 → L2 → L3 → RAM

## CPU
- 负责取指、解码、执行指令；高级语言需先经 ==编译器== 编译成机器码
- 可从 [[RAM]]、磁盘、缓存读写数据

## 主板
- 连接所有组件，提供数据流动路径

> [!note] 小结
> 从快到慢：缓存 > RAM > 磁盘。CPU 按 L1 → L2 → L3 → RAM 逐级查找。
```

**对比要点**：加了 `#` 标题与 frontmatter；把磁盘/RAM/缓存归入 `## 存储层次` 分组；长段落拆成 `- ` 列表；图片原位保留；`==高亮==` 保留；新增一处 `[[RAM]]` 双链和结尾 callout 小结。

完整成品见 `example-curated-note.md`。
